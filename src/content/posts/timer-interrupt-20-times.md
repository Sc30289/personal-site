## 一个看似奇怪的设计

做定时器实验时，题目要求「每隔 1 秒数码管加 1」。直觉方案是让定时器直接定时 1 秒，但 12MHz 晶振下根本做不到——这就引出了整个实验的核心：**分频**。

## 先算清楚一个机器周期

51 单片机的一个机器周期 = 12 个时钟周期。12MHz 晶振下：

```text
Tcy = 12 / 12MHz = 1μs
```

也就是说，定时器每计一个数，正好过去 1μs。

## 方式 1 最多只能定 65ms

T0 方式 1 是 16 位计数器，最大计数值 `2^16 = 65536`：

```text
最长定时 = 65536 × 1μs ≈ 65.536ms
```

离 1 秒差了 15 倍。所以只能「退一步」：先定一个短时基，再数次数。

## 50ms × 20 = 1s

选 50ms 作为时基，需要计数的机器周期数：

```text
N = 50000
初值 X = 65536 - 50000 = 15536 = 0x3CB0
TH0 = 0x3C, TL0 = 0xB0
```

每次中断重新装初值，中断 20 次就凑满 1 秒：

```c
void T0_ISR(void) interrupt 1
{
    TH0 = 0x3C;
    TL0 = 0xB0;
    if (++tick >= 20) {
        tick = 0;
        flag_1s = 1;
    }
}
```

## 为什么不是「中断里干所有事」

如果把数码管刷新、按键扫描都塞进中断，中断会越来越长，定时精度被拖垮，还容易丢中断。

正确做法是**前后台结构**：

- 前台（中断）：只做计数、置标志
- 后台（主循环）：检测标志，刷新显示、处理按键

```c
void main(void)
{
    init();
    while (1) {
        if (flag_1s) {
            flag_1s = 0;
            count = (count + 1) % 10;
            if (count == 0) beep(200);  // 归零提示音
        }
        display(count);   // 动态扫描
        keyscan();        // 按键消抖
    }
}
```

## 蜂鸣器复用同一个时基

短响 200ms 不需要第二个定时器：200ms 就是 4 个 50ms，数 4 次中断就行。一个时基驱动所有节拍，代码简单，也不会有两个定时器互相干扰的问题。

## 误差从哪来

理论上是精确的 1 秒，但实际会有微小误差：

1. 中断响应需要时间，重装初值也有几条指令的延迟
2. 晶振本身有频差
3. 中断被更高级中断打断

对数码管计数来说，这些误差可以忽略；如果要做时钟，得用自动重装的定时器模式（方式 2）或者外部 RTC。

## 小结

「1 秒中断 20 次」不是设计缺陷，而是 16 位定时器在 12MHz 下的必然选择。想清楚机器周期和初值计算，这类题就再也不会做错了。
